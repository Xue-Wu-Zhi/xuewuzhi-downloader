# 账号、登录与课程权限


## 两类账号要分清

课程平台账号决定你能看到哪些班级、课程和资料。下载器本身的账号、试用或会员安排属于另一套产品服务，不能为课程平台增加权限。

## 正常登录步骤

![课程账号登录与空列表排查示意](../../assets/guides/login-course.png)

*通用操作示意，使用虚构数据；不是客户端截图，具体界面以当前版本为准。* [查看大图](../../assets/guides/login-course.png)

1. 从客户端选择与实际上课应用一致的平台入口。
2. 在引导的登录窗口完成账号登录；验证码和二次验证按原平台要求处理。
3. 登录窗口返回后等待课程列表加载。
4. 核对显示的课程是否属于当前账号，必要时检查班级、企业或期次。

## 登录成功却没有课程

| 可能原因 | 可以做的检查 |
| --- | --- |
| 登录了另一手机号或绑定方式 | 在原平台确认该账号的课程列表 |
| PC、App 或企业入口不同 | 查看相应平台教程，换到实际上课入口 |
| 课程属于另一个企业或班级 | 在原平台核对组织和班级身份 |
| 课程未开放或权限已到期 | 检查原平台是否可以正常播放 |
| 会话已失效或平台改版 | 按客户端提示重新登录，再记录错误信息 |

## 登录异常时

确认系统时间与网络正常，保留准确错误提示。不要频繁重复提交验证码或同时打开多个登录流程。若原平台本身无法登录，应先解决原平台的问题。

## 保护自己的信息

不要把 Cookie、Token、验证码、二维码或账号缓存粘贴到 Issue。公开日志中应移除带鉴权参数的课程链接。开源骨架不需要任何真实账号，运行示例时也不应配置账号。[隐私与反馈](Privacy.md)
