# 组件与架构：公开示例


这是一份独立设计的教学骨架，用于表达课程软件的基本组件关系。图和类名不是官方客户端内部结构的披露，也不是可以直接接入客户端的插件协议。

```text
命令行入口
    ├── demo → 虚构课程提供方 → 课程 / 章节 / 资源 → 目录文本
    └── platforms → 本地公开元数据 → 名称筛选 → 教程链接

抽象边界
    CourseProvider   提供课程数据的约定
    DownloadEngine   引擎约定，仓库中没有具体实现
```

## 数据组件

| 类型 | 表达的概念 | 为什么单独存在 |
| --- | --- | --- |
| Course | 课程与所属章节 | 使展示层不依赖某个平台的数据格式 |
| Chapter | 一个章节及其资源 | 表示学习顺序和资源归属 |
| Resource | 标题、资源类别和示例文件名 | 演示视频、音频、文档的差异 |
| ResourceKind | 资源类别枚举 | 避免在演示中散落不一致的字符串 |
| Progress | 已完成数量、总量和消息 | 说明未来独立组件可如何描述进展 |

## 接口组件

`CourseProvider` 约定 `list_courses()`，示例实现只返回内置的虚构课程。`DownloadEngine` 约定 `run(course)`，这里仅有类型协议，没有解析、网络传输、调度或转换实现。

这些接口刻意保持通用，不包含平台地址、账号数据、签名、资源获取算法或内部协议。

## 可运行组件

`demo.py` 定义虚构课程并生成目录文本。`cli.py` 解析命令、运行示例，或读取本地 JSON 检索公开教程。平台 JSON 只包含名称、分类、标识和公开教程 URL。

## 扩展方向

适合练习的改进包括目录展示、类型约束、公开目录检索、文档生成和示例可访问性。若实现自己的独立组件，应明确其许可、授权前提和功能边界，不能宣称本骨架提供官方核心 SDK。
